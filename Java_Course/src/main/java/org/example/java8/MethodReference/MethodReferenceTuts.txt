📘 Java 8 Method Reference – Master Summary
🔷 What is a Method Reference?
A method reference is a shorthand syntax for a lambda expression that only calls a method.

FunctionalInterface<ReturnType> reference = (args) -> ClassName.method(args)
//Or
FunctionalInterface<ReturnType> reference = ClassName::method

🔰 Syntax Forms
Syntax	Description	Example
1. ClassName::staticMethod	Refers to a static method	Math::abs
2. object::instanceMethod	Refers to a method of a particular object	System.out::println
3. ClassName::instanceMethod	Refers to a method of any object of a given type	String::toUpperCase
4. ClassName::new	Refers to a constructor	Person::new

✅ All Examples
1. Static Method Reference
Function<Integer, Integer> square = MyClass::square;
System.out.println(square.apply(4)); // 16

2. Instance Method of a Particular Object
MyPrinter printer = new MyPrinter();
Consumer<String> c = printer::print;
c.accept("Hello"); // prints: Hello

3. Instance Method of an Arbitrary Object
Function<String, String> upper = String::toUpperCase;
System.out.println(upper.apply("java")); // JAVA

4. Constructor Reference
Function<String, Person> creator = Person::new;
Person p = creator.apply("Naruto");
System.out.println(p.name); // Naruto

🧩 With Custom Functional Interface
@FunctionalInterface
interface Printer {
    void print(String msg);
}

class MyClass{
    void display(String msg){
        System.out.println(msg);
    }

    public static void main(String[] args){
        MyClass myClass = new MyClass();
        Printer printer = myClass::display;
        printer.print("Hi Jarvis");
    }
}

🧠 Key Concepts Recap
Method Reference is a lambda shortcut used when calling an existing method directly.

"::" operator binds a method to a functional interface.

Compatible with both:

-> Built-in interfaces: Function, Predicate, Consumer, Supplier

-> Custom interfaces: if their method signature matches

Constructors can be referenced via ClassName::new, which is usable with interfaces like Function<T,R> or Supplier<R>.
Why with these functional interfaces only?
-> Because, they return an object, and constructor implicitly initialises an object and returns it.

Even though constructors don't use return, they implicitly return a fully-initialized object instance.

📘 Illustrative Summary:
// All in one place:

Function<Integer, Integer> staticRef = Math::abs;
Consumer<String> instanceRef = System.out::println;
Function<String, String> classInstanceRef = String::trim;
